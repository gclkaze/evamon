# Task: Execution Log Panel — Fyne UI Only

## Overview
Build the ExecutionLogPanel Fyne UI for EVAMON. The backend is already
implemented — ExecutionLogRegistry, TriggerExecution, RingBuffer,
TriggerExecutionCoordinator, triggerStreamTracker, and drainStream are
all done. This task is UI only.

its own toolbar with: maximize, detach, string filter, operation type

diagram tab → rule tab → execution list → execution detail.

## 1. ExecutionLogParser

`ui/execution_log/execution_log_parser.go`

Parse structured EVA log lines of the form:
```
Line:<N> <Name> <Type> <Phase>
```

Where `<Type>` is one of: `Operation`, `Label`, `Program`.
Non-matching lines are considered free-form.
```go
type OperationType string

const (
    OperationTypeAll       OperationType = "All"
    OperationTypeOperation OperationType = "Operation"
    OperationTypeLabel     OperationType = "Label"
    OperationTypeProgram   OperationType = "Program"
    OperationTypeFreeForm  OperationType = ""
)

type ParsedLogLine struct {
    Raw           string
    LineNumber    int           // 0 if not structured
    Name          string        // e.g. "MetricsIndexSave"
    OperationType OperationType // empty if free-form
    Phase         string        // "Start", "End", or ""
    IsStructured  bool
}

func ParseLogLine(raw string) ParsedLogLine
```

Implementation notes:
- Split on space — expect at least 4 tokens after "Line:N"
- Extract line number via `strings.TrimPrefix(tokens[0], "Line:")`
- Token[2] is OperationType — match against known types case-insensitively
- Token[3] is Phase
- If parsing fails at any point return `ParsedLogLine{Raw: raw, IsStructured: false}`

    if exec == nil {
        return
    }
    dialog.ShowFileSave(func(uc fyne.URIWriteCloser, err error) {
        if err != nil || uc == nil {
            return

        defer uc.Close()
        p.writeExecutionJSON(uc, exec)

    enc := json.NewEncoder(w)
    enc.SetIndent("", "  ")
    return enc.Encode(exec)
}

`TriggerExecution` from the active rule tab's detail view.
Returns nil if the detail view is not currently shown.

### Auto-refresh
```go
func (p *ExecutionLogPanel) startAutoRefresh() {
    ticker := time.NewTicker(500 * time.Millisecond)
    go func() {
        defer ticker.Stop()
        for {
            select {
            case <-ticker.C:
                p.refresh()
            case <-p.stopCh:
                return
            }
        }
    }()
}

func (p *ExecutionLogPanel) refresh() {
    for _, dt := range p.diagTabs {
        dt.Refresh()
    }
}
```

All Fyne widget mutations inside `refresh()` must be safe to call
from a goroutine. Use `canvas.Refresh(widget)` for redraws.
Where content rebuild is needed wrap in a channel signal to the
main thread rather than mutating widgets directly from the goroutine.

### Filter logic

Both filters apply simultaneously (AND). A line passes if:
```go
func (v *ExecutionDetailView) linePassesFilter(entry models.ExecutionLogEntry) bool {
    parsed := ParseLogLine(entry.ParsedMsg)
    if v.filterType != OperationTypeAll && v.filterType != "" {
        if parsed.OperationType != v.filterType {
            return false
        }
    }
    if v.filterText != "" {
        if !strings.Contains(
            strings.ToLower(entry.ParsedMsg),
            strings.ToLower(v.filterText),
        ) {
            return false
        }
    }
    return true
}
```

`ApplyFilterText(text string)`:
- Sets `v.filterText = text`
- Calls `v.rebuildLines()`

`ApplyFilterType(t OperationType)`:
- Sets `v.filterType = t`
- Calls `v.rebuildLines()`

`rebuildLines()`:
- Iterates `v.currentExec.Lines`
- Applies `linePassesFilter`
- Rebuilds `v.linesBox.Objects`
- Calls `v.linesBox.Refresh()`
- Calls `v.scroll.ScrollToTop()`

If no lines pass the filter show centered label:
"No lines match the current filter."

If `currentExec.Lines` is empty show:
"No output captured."

## 10. Coding standards

- No method longer than 20 lines.
- All structs use private fields with public constructor functions.
- No business logic in UI files — read from ExecutionLogRegistry only.
- Widget construction happens in constructors only — never in Refresh()
  or filter methods. Refresh/filter only mutates .Objects and calls
  .Refresh() on existing containers.
- filepath.Base() everywhere a file path is displayed.
- fyne.CurrentApp() used inside onDetach to create the new window.
- All goroutine→UI communication must be thread safe — use
  canvas.Refresh() for redraws, never mutate widget state from
  a non-main goroutine directly.
- ParsedMsg is always shown — never the raw Line field.
- OperationType constants defined in execution_log_parser.go and
  used across all UI files in the package.

## 3. Execution status styling in ExecutionListView

Update `ui/execution_log/execution_list_view.go`.

Each execution row must visually reflect its status:

- **In progress** (`exec.FinishedAt == nil`):
  status text = "…", no color change, default style
- **Success** (`*exec.Success == true`):
  status text = "✓", status label color = `color.NRGBA{R:0, G:180, B:0, A:255}`
- **Failed** (`*exec.Success == false`):

Each row is a `container.NewHBox` of individual labels rather than
a single `widget.Button`, so each label can be styled independently:
```go
func (v *ExecutionListView) buildRow(
    index int,
    exec *models.TriggerExecution,
) fyne.CanvasObject {
    indexLabel  := widget.NewLabel(fmt.Sprintf("#%d", index))
    timeLabel   := widget.NewLabel(exec.StartedAt.Format("15:04:05"))
    fileLabel   := widget.NewLabel(filepath.Base(exec.FilePath))
    statusLabel := v.buildStatusLabel(exec)
    row := container.NewHBox(indexLabel, timeLabel, fileLabel, statusLabel)
    return v.wrapClickable(row, exec)
}

func (v *ExecutionListView) buildStatusLabel(exec *models.TriggerExecution) *canvas.Text {
    if exec.FinishedAt == nil {
        return canvas.NewText("…", theme.ForegroundColor())
    }
    if *exec.Success {
        return canvas.NewText("✓", color.NRGBA{R: 0, G: 180, B: 0, A: 255})
    }
    return canvas.NewText("✗", color.NRGBA{R: 200, G: 0, B: 0, A: 255})
}
```

and custom layout, OR use `desktop.Hoverable` + `fyne.Tappable` on

```go
func (v *ExecutionListView) wrapClickable(

package execution_log

import (
    "encoding/json"
    "image/color"
    "os"
    "strconv"
)

type OperationStyle struct {
    BorderColor string `json:"borderColor"`
    BadgeColor  string `json:"badgeColor"`
    BadgeText   string `json:"badgeText"`
}

type LogStyleConfig struct {
    Styles        map[string]OperationStyle `json:"styles"`
    FreeFormColor string                    `json:"freeFormColor"`
}

func LoadLogStyleConfig(path string) (*LogStyleConfig, error) {
    data, err := os.ReadFile(path)
    if err != nil {
        return defaultLogStyleConfig(), nil // fallback to defaults
    }
    var cfg LogStyleConfig
    if err := json.Unmarshal(data, &cfg); err != nil {
        return defaultLogStyleConfig(), nil
    }
    return &cfg, nil
}

func (c *LogStyleConfig) StyleFor(opType OperationType) (OperationStyle, bool) {
    s, ok := c.Styles[string(opType)]
    return s, ok
}

func (c *LogStyleConfig) FreeFormColorParsed() color.Color {
    return parseHexColor(c.FreeFormColor)
}

func defaultLogStyleConfig() *LogStyleConfig {
    return &LogStyleConfig{
        Styles: map[string]OperationStyle{
            "Label":     {BorderColor: "#4A90D9", BadgeColor: "#4A90D9", BadgeText: "Label"},
            "Operation": {BorderColor: "#E6A817", BadgeColor: "#E6A817", BadgeText: "Operation"},
            "Program":   {BorderColor: "#7B68EE", BadgeColor: "#7B68EE", BadgeText: "Program"},
        },
        FreeFormColor: "#888888",
    }
}

func parseHexColor(hex string) color.NRGBA {
    hex = strings.TrimPrefix(hex, "#")
    if len(hex) != 6 {
        return color.NRGBA{R: 128, G: 128, B: 128, A: 255}
    }
    r, _ := strconv.ParseUint(hex[0:2], 16, 8)
    g, _ := strconv.ParseUint(hex[2:4], 16, 8)
    b, _ := strconv.ParseUint(hex[4:6], 16, 8)
    return color.NRGBA{R: uint8(r), G: uint8(g), B: uint8(b), A: 255}
}
```

### 4c. LogLineRenderer

Create `ui/execution_log/log_line_renderer.go`:
```go
package execution_log

type LogLineRenderer struct {
    config *LogStyleConfig
}

func NewLogLineRenderer(config *LogStyleConfig) *LogLineRenderer {
    return &LogLineRenderer{config: config}
}

func (r *LogLineRenderer) Render(entry models.ExecutionLogEntry) fyne.CanvasObject {
    parsed := ParseLogLine(entry.ParsedMsg)
    if !parsed.IsStructured {
        return r.renderFreeForm(entry.ParsedMsg)
    }
    return r.renderStructured(entry.ParsedMsg, parsed.OperationType)
}

func (r *LogLineRenderer) renderStructured(msg string, opType OperationType) fyne.CanvasObject {
    style, ok := r.config.StyleFor(opType)
    if !ok {
        return r.renderFreeForm(msg)
    }
    borderColor := parseHexColor(style.BorderColor)
    badgeColor  := parseHexColor(style.BadgeColor)
    return r.buildRenderedLine(msg, borderColor, badgeColor, style.BadgeText)
}

func (r *LogLineRenderer) renderFreeForm(msg string) fyne.CanvasObject {
    borderColor := r.config.FreeFormColorParsed()
    return r.buildFreeFormLine(msg, borderColor)
}

func (r *LogLineRenderer) buildRenderedLine(
    msg string,
    borderColor, badgeColor color.Color,
    badgeText string,
) fyne.CanvasObject {
    bar   := r.buildLeftBar(borderColor)
    badge := r.buildBadge(badgeText, badgeColor)
    label := widget.NewLabelWithStyle(msg, fyne.TextAlignLeading, fyne.TextStyle{Monospace: true})
    return container.NewHBox(bar, badge, label)
}

func (r *LogLineRenderer) buildFreeFormLine(
    msg string,
    borderColor color.Color,
) fyne.CanvasObject {
    bar   := r.buildLeftBar(borderColor)
    label := widget.NewLabelWithStyle(msg, fyne.TextAlignLeading, fyne.TextStyle{Monospace: true})
    return container.NewHBox(bar, label)
}

func (r *LogLineRenderer) buildLeftBar(c color.Color) fyne.CanvasObject {
    rect := canvas.NewRectangle(c)
    rect.SetMinSize(fyne.NewSize(4, 20))
    return rect
}

func (r *LogLineRenderer) buildBadge(text string, c color.Color) fyne.CanvasObject {
    bg    := canvas.NewRectangle(c)
    label := canvas.NewText(text, color.White)
    label.TextSize = 10
    label.TextStyle = fyne.TextStyle{Bold: true}
    bg.SetMinSize(fyne.NewSize(float32(len(text))*7+8, 18))
    return container.NewStack(bg, container.NewCenter(label))
}
```

  # Task: ExecutionResult message handling in drainStream

## Overview
EVACRON sends two types of messages over the stream WebSocket during
a trigger execution:

1. **Log lines** — `ExecutionOutput` — streamed during execution
2. **Final result** — `ExecutionResult` — sent once when execution ends

The two message types are discriminated by the presence of the
`success` key in the JSON — only `ExecutionResult` carries it.
`ExecutionOutput` never has a `success` field.

When an `ExecutionResult` message is received, the stream for that
trigger is considered complete. The result carries a success/failure
flag and an optional error message.

Examples of each message type:
```json
// ExecutionOutput — log line during execution
{"jobId":"3dfc21a8-...","filePath":"C:/Scripts/main.eva","stream":"stderr","line":"Program Start."}

// ExecutionResult — success
{"jobId":"3dfc21a8-...","success":true}

// ExecutionResult — failure
{"jobId":"3dfc21a8-...","success":false,"error":"exit status 1"}
```

## Message discrimination

The discriminator is the presence of the `success` key in the raw
JSON. Use `map[string]json.RawMessage` to check for the key before
attempting full unmarshalling:
```go
func (inst *WidgetService) tryParseResult(text string) (models.ExecutionResult, bool) {
    var raw map[string]json.RawMessage
    if err := json.Unmarshal([]byte(text), &raw); err != nil {
        return models.ExecutionResult{}, false
    }
    if _, hasSuccess := raw["success"]; !hasSuccess {
        return models.ExecutionResult{}, false
    }
    var result models.ExecutionResult
    if err := json.Unmarshal([]byte(text), &result); err != nil {
        return models.ExecutionResult{}, false
    }
    return result, true
}
```

This correctly handles all cases:
- `{"jobId":"...","success":true}` → ExecutionResult ✓
- `{"jobId":"...","success":false,"error":"exit status 1"}` → ExecutionResult ✓
- `{"jobId":"...","filePath":"...","line":"..."}` → ExecutionOutput ✓

## handleStreamLine and related methods
```go
func (inst *WidgetService) handleStreamLine(
    msg  *models.TriggerOperationMsg,
    text string,
) {
    if result, ok := inst.tryParseResult(text); ok {
        inst.handleExecutionResult(msg, result)
        return
    }
    inst.handleOutputLine(msg.ID, text)
}

func (inst *WidgetService) handleOutputLine(triggerID, text string) {
    var output models.ExecutionOutput
    if err := json.Unmarshal([]byte(text), &output); err != nil {
        return
    }
    if output.Line == "" {
        return
    }
    inst.streamTracker.recordLine(triggerID, output)
}

func (inst *WidgetService) handleExecutionResult(
    msg    *models.TriggerOperationMsg,
    result models.ExecutionResult,
) {
    if !result.Success && result.Error != "" && result.Error != "exit status 1" {
        inst.streamTracker.recordError(msg.ID, result.Error)
    }
    inst.streamTracker.completeWithResult(msg, result.Success)
}
```

---

## Error suppression rule

- `result.Success == true` → complete immediately, no error handling
- `result.Success == false` and `result.Error == "exit status 1"` →
  suppress the error, do NOT add to log lines, complete as failed
- `result.Success == false` and `result.Error` is any other non-empty
  string → record as a log line via `recordError`, then complete as failed
- `result.Success == false` and `result.Error == ""` → complete as
  failed, nothing to log

## Update drainStream

Completion is triggered inside `handleStreamLine` when an
`ExecutionResult` is detected — not at the end of `drainStream`.
The stream end marker and final acknowledgement remain unchanged
as they are part of the WebSocket protocol handshake.
```go
func (inst *WidgetService) drainStream(
    ctx    context.Context,
    client *wsclient.Client,
    msgID  string,
    msg    *models.TriggerOperationMsg,
) error {
    if err := client.SendText(ctx, TRIGGER_PROTOCOL_ACKNOWLEDGEMENT); err != nil {
        return err
    }
    inst.streamTracker.updateStatus(msgID, models.TriggerOperationStatusAck)

    for {
        text, err := client.ReadText(ctx)
        if err != nil {
            return err
        }
        if text == TRIGGER_STREAM_END {
            break
        }
        if inst.logger != nil {
            inst.logger.Info(fmt.Sprintf("[trigger %s] %s", msgID, text))
        }
        inst.handleStreamLine(msg, text)
    }

    _ = client.SendText(ctx, TRIGGER_PROTOCOL_ACKNOWLEDGEMENT)
    return nil
}
```

## Coding standards

- No method longer than 20 lines.
- All structs use private fields with public constructor functions.
- The presence of the `success` JSON key is the sole discriminator
  between `ExecutionResult` and `ExecutionOutput` — never use
  `jobId` alone as the discriminator.
- `result.Error == "exit status 1"` is the only suppressed error
  string — all other non-empty errors are recorded as log lines.
- Never set or render `Stream` field anywhere — it is irrelevant.
- `OnDone` always receives `success` explicitly — never infer it
  from `msg.Status`.
- `tryParseResult` uses `map[string]json.RawMessage` for key
  presence check before full unmarshal — never rely on zero values
  to discriminate message types.
